# 本机知识库管理网页

用户要求维护已有向量数据库，包含原数据增删改查；确认先做仅本机使用。沿用已有独立开发副本与本地服务，不修改上游原副本，不部署到公网。本轮“先做”作为直接执行指令，采用当前会话实施，保留设计与验证记录。

## 目标

独立后台监听 `127.0.0.1:18080`，管理多个项目；浏览原始资料、编辑提取后的正文、上传/下载源文件、回收站、分片预览、索引重建与状态、检索测试、JSON备份与追加恢复。默认模型、端口和 structure-v2 算法沿用现有实现，不引入新模型或云端推理。

## 方案与取舍

1. 只给 Chroma 加表格：可以浏览记录，但无法可靠维护原文、重新分片和识屏缓存，不采用。
2. 将全部原文立即迁移到新服务：长期统一，但会改变现有资料的权威存储，当前不采用。
3. 独立网页 + 项目适配器（采用）：新项目由服务维护；识屏通过本机鉴权桥接到运行中的桌面进程，调用同一变更队列、索引与缓存。识屏关闭时明确显示未连接，禁止绕过它写文件。当前设计选择由实现者作出，以保护已导入资料。

## 数据和一致性

- 识屏仍以 userData/knowledge 为权威，HTTP 桥接由桌面进程监听随机回环端口，发现文件保存于 userData/rag/admin-bridge.json、权限0600，包含随机令牌。
- 新项目放在 `local-rag/data/admin/projects/<uuid>/`，独立集合前缀 `rag_admin_`。资料正文及元数据原子写入，上传的原始二进制文件独立保存。
- 网页修改带版本号，过期编辑返回409；变更串行执行。先持久保存正文，再更新文档快照并安排索引，索引失败不会丢失原文，显示可重试错误。
- 删除为软删除，可恢复；软删除和编辑立即阻止旧索引用于该资料。分片为派生结果，用户通过编辑原文及重建修正，第一版不直接手改向量。
- 识屏和托管新项目复用 RagIndex、structure-v2、BGE-M3及BM25/RRF。现有未托管集合只能浏览记录，避免破坏其他程序的权威数据。旧v1集合不写。
- 文件上限30MiB，提取正文上限2,000,000字符；支持TXT/Markdown/PDF/DOCX，扫描PDF无OCR时说明。原有桌面导入限制保持兼容，网页通道使用更大的正文限制。
- 备份包含正文、元数据和能取得的原文件；恢复为追加新资料，不覆盖已有ID。第一版JSON备份请求最多45MiB，超过明确报错；大规模数据库物理备份仍使用现有停止服务后backup。

## 网页

侧栏列出项目、资料/分片/检索/任务/备份及服务集合入口。正文列表支持搜索与回收站筛选。编辑器显示来源和版本，保存后刷新索引状态；上传支持多文件逐个提交，逐项反馈错误。检索显示来源、章节、分数和正文。服务页区分托管项目与未托管集合，显示连接状态。使用系统字体、浅色正文与深色侧栏，不依赖CDN。

## 本机边界

仅绑定127.0.0.1；严格Host与Origin检查；禁止跨域；页面会话使用HttpOnly、SameSite=Strict cookie，写操作需要随机CSRF令牌及JSON类型。静态路径固定，文件下载只按项目和资料ID查找，上传名称不能选择本地路径。文档正文只按文本渲染，原始文件强制附件下载。原文、元数据和服务令牌不写入源码、日志或公开GitHub。

## 交付

新增手动启动网页的快捷方式、停止方式与API说明；更新服务管理与卸载台账。更新识屏独立试用版以启用桥接，先备份现有应用与知识库文件。本轮只本机交付，GitHub代码同步不自动执行。

## 验证

隔离临时目录做真实存储与HTTP检查，外部模型/数据库调用在单元测试中使用明确模拟；真实本机集成使用新建合成测试项目，不修改用户课程资料。覆盖过期版本、软删除/恢复、路径/Host/Origin/CSRF、解析错误、索引失败重试、备份追加、保留外部集合、桌面缓存即时同步。完成后运行原软件全套测试、类型检查、构建、服务测试与网页实际操作，并做一次独立审查。

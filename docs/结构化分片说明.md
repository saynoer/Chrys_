# 结构化分片 v2

已更新到独立试用版 `3.4.0-rag.2`，不需要新增模型或充值才能构建本地索引；生成回答仍需你的AI平台余额。

## 现在怎样分片

- 按Markdown的`#`标题层级，以及可明确识别的短数字章节标题划分区域，不跨章节拼接。
- 章节内优先保留段落、普通长度的表格、围栏代码块。围栏内的`#`不会当成文章标题。
- 目标约600字符；为了保留完整结构，单片正文允许放宽至1200字符。
- 超长段落或代码/表格先找换行、句末边界，最后才按长度切开。并不保证超长结构仍在同一片里。
- 普通链接、Markdown超链接及其平衡括号尽量完整保留。不可安全容纳的超长链接会明确报错，不无限切分或静默截断。
- 重叠从固定100字符改为最多100字符的适应性重叠，优先完整行/句；章节边界、表格和代码块不机械重复。
- 每片保留原文起止位置和章节路径。章节会一起参与向量生成、BM25检索，并在来源预览里显示。

这仍是确定性的结构切分，没有调用LLM逐段判断语义，也不是完整Markdown排版解析器。OCR错误、图片里的文字、没有真实URL的“视频链接”占位，不能单靠分片恢复。

## 如何使用

打开同一个“识屏RAG试用”，版本号应为 `3.4.0-rag.2`。设置→资料库中继续选“本地检索”；索引已替你重建。导入或编辑资料后，按页面提示更新索引。

本次重建只用本地Ollama与Chroma，没有发起DeepSeek付费请求。余额不足、语音转录错误、生成模型未遵循证据等，仍属于分片之外的环节。

# 本地知识库管理网页

本机地址：[http://127.0.0.1:18080](http://127.0.0.1:18080)。仅本机可以访问，不在公网发布，不需要新增云端模型或填写网页账户。

## 打开与停止

双击同目录的 `启动本地知识库管理.command`。它会构建并启动网页、复用现有Ollama和Chroma，并打开独立的“识屏RAG试用”与浏览器。

双击 `停止本地知识库管理.command` 只停止网页后台，向量模型和数据库继续供其他项目使用。关闭浏览器标签不会停止后台。停止整套本地服务仍使用：

```sh
local-rag/runtime/chroma-env/bin/python local-rag/scripts/manage.py stop
```

## 日常使用

1. 左侧选择 **识屏资料库**，即可维护原有识屏资料；也可以新建独立知识库供另一个项目使用。
2. 在 **资料库** 上传PDF、DOCX、Markdown、TXT，或新建文本。每个文件最多30MB，提取后的正文最多200万字符。图片扫描PDF没有自动OCR，提取不到文字会提示。
3. 点击资料名称编辑正文、名称、标签及适用场景，选择 **保存并更新索引**。保存正文不会改写上传时的源文件。网页上传的文件会保留独立原文件副本；识屏历史导入资料仍从旧路径读取源文件，找不到时可下载提取后的正文。
4. **分片浏览** 显示已保存正文的章节、片段和原文位置；修改原文后重新生成片段，不直接手改向量数值。
5. **索引任务** 显示正在更新、就绪或失败原因。失败不会删除原文，修复连接后点击重新建立。旧版本编辑会被拒绝，当前输入保留供合并。
6. **检索测试** 输入问题，查看真实命中的原文片段。只执行本地检索，不生成云端答案、不消耗DeepSeek或阿里云额度。排序分用来比较检索结果，不是回答正确率。
7. **移除** 先放入回收站，同时停止参与检索；在回收站可以恢复。新试用版的桌面资料移除也改为可恢复。
8. **备份与恢复** 下载JSON备份，包含正文、元数据、回收站和可取得的源文件。恢复为新增资料，使用新编号，不覆盖现有资料；重复恢复会产生多份资料。

## 与识屏同步

识屏资料仍由桌面程序统一保存，网页通过本机连接交给同一写入队列处理。维护识屏资料时，请保持更新后的 `3.4.0-rag.3` 试用版运行；关闭后网页会显示未连接，不会绕过程序修改原文文件。

桌面与网页同时编辑时，保存会检查版本。旧编辑窗口不能覆盖更新内容；遇到冲突先复制需要保留的文字，再重新加载资料合并。

其他网页新建的知识库可以独立使用，不要求识屏运行。每个知识库拥有独立的资料目录和向量集合，仍共享同一个本地模型和数据库。

**服务与集合** 可以只读浏览全部现有向量集合，包括旧版识屏集合和其他项目集合。未由本后台托管的集合不会被直接修改或删除；其完整原文需要由原项目提供。

## 本机文件与移除

| 内容 | 路径（项目根目录下） |
| --- | --- |
| 网页源码与静态界面 | `local-rag/web/` |
| 网页构建结果 | `local-rag/web/dist/server.cjs` |
| 新建知识库的正文、原文件与索引记录 | `local-rag/data/admin/projects/` |
| 网页服务进程记录 | `local-rag/run/admin.json` |
| 网页后台日志 | `local-rag/logs/admin.log` |
| 识屏管理连接记录 | `local-rag/data/shiping-trial/rag/admin-bridge.json` |
| 本次更新前的应用与知识资料备份 | `local-rag/backups/before-web-admin/` |
| Node运行入口 | `local-rag/runtime/node/bin/node`（复用已有Node的链接） |

当前Node入口指向Codex已有运行环境，不是新安装的一份全局Node；移除本项目时只删除这个链接，不删除链接指向的Codex文件。不修改系统PATH，不添加开机任务。

要停用网页，停止admin即可。要移除网页新建的知识库，先导出备份；其资料、源文件和向量集合是一组，应共同核对。第一版未提供永久清空回收站、删除整个项目或直接删除外部向量集合的按钮，避免误删共享资料。完整卸载仍按《本地RAG使用与卸载》与操作台账核对；卸载预览会识别网页新项目并阻止误判为“只有识屏在使用”。

JSON备份单次最多45MB，超过时请先退出识屏并停止服务，再使用现有的整套服务备份方式。备份可能包含私人资料，请自行选择保存位置；不包含AI密钥和运行环境。

## 给其他项目使用的接口

网页的管理与检索接口也可以给本机程序使用。先请求 `GET /api/session`，保留响应Cookie和返回的 `csrf`；写请求使用JSON，并带 `Origin: http://127.0.0.1:18080` 和 `X-Rag-CSRF: <csrf>`。服务重启后重新取得会话。跨站调用不开放。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/health` | 检查本地模型、数据库、识屏连接 |
| `GET /api/projects` | 列出项目 |
| `POST /api/projects` | 创建项目，正文 `{"name":"项目名称"}` |
| `GET /api/projects/{项目ID}/documents` | 资料列表，可带 `q` 搜索和 `trash=1` |
| `POST /api/projects/{项目ID}/documents` | 新建正文，字段 `name,text,tags,modes` |
| `GET /api/projects/{项目ID}/documents/{资料ID}` | 读取正文及 `version` |
| `PUT /api/projects/{项目ID}/documents/{资料ID}` | 更新，必须带读取时的 `version` |
| `DELETE /api/projects/{项目ID}/documents/{资料ID}` | 移入回收站，JSON中带 `version` |
| `POST /api/projects/{项目ID}/documents/{资料ID}/restore` | 恢复资料，带 `version` |
| `POST /api/projects/{项目ID}/import` | 上传，字段 `name` 与原文件的 `base64` |
| `GET /api/projects/{项目ID}/documents/{资料ID}/original` | 下载源文件；没有时导出正文 |
| `GET /api/projects/{项目ID}/documents/{资料ID}/chunks` | 已保存正文的分片，支持 `offset,limit` |
| `GET /api/projects/{项目ID}/status` | 当前索引状态 |
| `POST /api/projects/{项目ID}/rebuild` | 异步重建，正文 `{}`，轮询status等待完成 |
| `POST /api/projects/{项目ID}/search` | 检索，字段 `query` 和 `mode`（conversation/screenshot） |
| `GET /api/projects/{项目ID}/backup` | 下载资料备份 |
| `POST /api/projects/{项目ID}/restore` | 从JSON备份追加资料 |
| `GET /api/collections` | 只读列出底层集合 |
| `GET /api/collections/{集合ID}/records` | 只读分页查看记录，支持 `offset,limit` |

`shiping` 为识屏项目ID。新项目ID由服务返回，集合名称以 `rag_admin_` 开头。`modes`默认为两种场景，空数组表示保留资料但不参与这两种场景检索。版本冲突返回409，请重新读取后合并，不能盲目覆盖重试。

接口返回原文片段，其他项目可自行交给回答模型；仍没有统一的 `/ask` 云端回答接口。原来的Ollama `11435`、Chroma `18000` 接口保持兼容。

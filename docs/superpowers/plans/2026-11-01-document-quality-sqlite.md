# Chrys 资料存储、解析清洗与索引实施计划（SQLite修订版）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans after implementation authorization. 本轮只编写计划，不修改功能或迁移数据。

**Goal:** 使原件、文档版本、逐页解析、清洗复核和RAG索引形成可追溯、可恢复的数据链。
**Architecture:** 本地文件保存不可变原件与资产；SQLite为业务事实唯一主库；Chroma为可重建的派生检索索引。桌面与网页共用存储和处理核心。
**Tech Stack:** 现有Electron/TypeScript、本地OCR、BGE-M3和Chroma；SQLite驱动在任务0验证两种运行时与打包兼容后锁定，不默认增加云端服务。
**Spec:** 用户提供的文件体检、逐页分类、分类解析、统一结果、质量验收流程；用户确认需保留统一结果字段；前版详细规则见 `2026-11-01-document-quality-final.md`。本修订版取代前版实施顺序和主存储方式，前版清洗细节仍适用。

## Global Constraints
- 全部本地解析；不执行文档宏、外部链接或文档中的指令，不调用云端OCR或多模态解析。
- 原文件不可覆盖；JSON/Markdown为导出格式，不与SQLite形成两套并行主记录。
- 初期保留现有30MB文件限制及页数/像素/解压防护；任务分阶段执行，阈值以受限样例验证后记录。
- 不自动批量重处理旧资料，不清空现有集合，不推测缺失页码或置信度。
- 本机磁盘运行SQLite，不把数据库放共享网盘；collection只提供逻辑分组，不能代替权限检查。

## Review Focus
多进程写入/版本冲突；SQLite与文件/Chroma跨存储失败；旧原件缺失；页码或OCR内容遗漏；备份遗漏WAL或资产。

## 一、存储分工与数据关系

建议集中于本项目受控的数据根目录：

```text
local-rag/data/library/
  chrys.sqlite          业务记录、正文、状态与引用
  originals/            不可变原文件，以文件编号或哈希关联
  assets/               页面截图、图片及公式/表格截图
  work/                 有生命周期的临时处理文件
  exports/              按需生成的Markdown/JSON导出
```

模型与Chroma数据继续在各自既有目录，不挪入SQLite。桌面和管理服务从同一配置读取数据根路径，不硬编码当前用户名；路径不一致时提示连接问题，不能悄悄创建第二份资料库。

### SQLite建议实体

| 实体 | 主要职责 |
| --- | --- |
| projects | 知识库、类型、兼容旧项目ID |
| documents | 逻辑资料、启用模式、软删除状态、当前修订 |
| source_files | 文件名、哈希、字节数、内部路径、格式和文件体检信息 |
| document_revisions | 原件关联、父版本、规则/引擎版本、解析正文与清洗正文 |
| pages | 页码或其他来源位置、尺寸、方向、类型、解析方法、状态 |
| elements | 标题、段落、列表、表格等元素、阅读顺序与坐标 |
| assets | 截图/嵌入图片及哈希、来源与位置 |
| cleaning_changes | 修改前后、规则、理由及接受/恢复状态 |
| quality_issues | 问题类型、严重程度、定位与复核结论 |
| processing_jobs / job_pages | 阶段、页级进度、重试、取消、恢复信息 |
| chunks | 分片正文、来源范围、修订、分片规则和内容哈希 |
| index_generations / index_tasks | 集合、模型指纹、构建状态及重试记录 |
| project_activation | 该项目活动修订快照及索引代际指针 |
| schema_migrations | 数据库升级版本与执行记录 |

所有业务实体关联project/document/revision。SQLite外键和事务约束关系，编辑使用版本号做乐观并发检查；不能只靠网页刷新防覆盖。

Chroma只保留向量、必要片段正文，以及projectId/docId/revisionId/chunkId、页/章节等必要元数据；不保存完整原件、清洗历史、密码或任务主状态。检索结果通过chunkId回SQLite校验活动状态并定位原文。

## 二、分阶段实施

### 阶段0：兼容验证、备份和基线

**文件：** 新增 `chrys/src/main/library/` 存储抽象及验证脚本；测试放 `chrys/tests/library-*.test.cjs`。
- [ ] 记录当前资料/字符/分片数量、启用模式、软删除和项目状态；建立现有测试题及性能基线，不在报告记录正文或密钥。
- [ ] 对当前JSON/正文/原件/向量记录做可恢复备份，明确缺失原件。
- [ ] 验证SQLite驱动在实际Node后台、Electron开发环境及打包应用中运行；验证事务、外键、WAL和并发写入。若依赖需原生编译，验证安装/签名再决定，不能只依据开发环境通过。
- [ ] 锁定驱动与schema v1；不增加常驻数据库服务器。
**通过条件：** 打包应用和网页可访问同一测试库；并发与回滚测试通过；备份恢复演练通过。

### 阶段1：SQLite主库和旧数据迁移

**文件：** `library/{schema,repository,assets,migrations}.ts`；适配 `knowledge.ts`、`knowledge-admin.ts`、网页 `store.ts`、桥接与IPC。
- [ ] 先为资料创建/编辑/软删除/恢复/模式选择/版本冲突写失败测试，再实现共享repository。解析、OCR及向量请求均不得放入长数据库事务。
- [ ] SQLite启用外键、短事务、有限写入等待和忙碌重试；后台和桌面进程分别建立连接；升级使用独占迁移锁及schema版本检查。
- [ ] 文件先写临时路径、校验并原子改名，再提交引用事务。失败时可识别未引用资产，提供清理预览；引用不存在的文件不得标为成功。
- [ ] 先迁移至独立候选库：保留原docId、项目、正文、模式、时间、回收站、人工编辑和关联状态，脚本可重复执行不重复生成资料。
- [ ] 桌面原件路径有效时复制原件快照；路径失效时记录原件缺失，保留现有正文，不伪造文件哈希或PDF页码。
- [ ] 校验各项目数量、正文哈希、软删除及模式后，短暂停写并最终核对，再切换到SQLite。旧文件只读保留；不长期双写。
- [ ] 当前Chroma作为legacy活动索引继续读取；库内保存兼容映射，不要求迁移时立刻重算全部向量。
**通过条件：** 数据校验一致、桌面/网页CRUD一致；重复迁移无新增副本；切换失败可退回原存储。
**回退边界：** 开放SQLite新写入前可直接退回旧快照；开放新写入后不能简单指回旧文件，须先导出并核对增量或恢复同一时点备份，避免丢失新修改。

### 阶段2：文件体检、后台任务及逐页解析

**文件：** `document-processing/{preflight,jobs,classifier,page-parser,result}.ts`；适配 `document-import.ts`、`document-worker.ts`、`document-pdf.ts`。
- [ ] 入口创建原件记录/导入事件；同项目哈希与处理配置一致时复用。哈希相同但规则改变可重处理；不同哈希仅在重新导入或人工关联时作为同一资料的新版本。
- [ ] 文件体检读取总页数/加密/可打开性，不负责正文提取；密码只在当前任务内存保存。修复只针对副本且限制尝试次数，保存修复件关联。
- [ ] 任务接口返回jobId，支持查询/取消/失败重试。持久化页级检查点，重启后核对未完成步骤，不能把中断页当成功页。
- [ ] 综合有效文字、乱码、图像覆盖、坐标和重复边缘文本分类为文本/扫描/混合/疑似复杂/异常；保存依据，不确定则复核。
- [ ] 文本页取正文及位置；扫描页OCR；混合页补识别重要候选图片区，位置与文字去重；异常页走备用本地路线或复核。
- [ ] 旋转元数据规范化；图像校正记录坐标变换。图片/Office沿用其来源位置体系。
- [ ] 页面按原顺序入库，空白页不生成正文但保留记录。将页数缺口、失败、乱码、疑似遗漏列入质量问题。
**通过条件：** 五类页面样例都有可追溯结果，页记录覆盖率100%；损坏/密码/超时/取消可见且不修改正式索引。

### 阶段3：清洗规则、统一结果与人工复核

**文件：** `document-processing/{cleaner,quality}.ts`、网页处理报告/预览、桌面任务入口。
- [ ] 保守识别重复页眉页脚、连续页码和水印，结合坐标/跨页证据；规则产生候选改动，不破坏原解析元素。
- [ ] 断行/断词修复保护标题、列表、URL、数字、代码、表格及公式；不以语言模型改写原意。
- [ ] 保留原生文字与OCR来源，重叠区域去重；扫描预处理前后可比较，效果恶化可回退。
- [ ] 第一份逐页结果起即保留文件/修订、页码、标题正文、列表、可靠表格、图片公式位置、复核标记；不是第三期才补来源。
- [ ] SQLite保存正式结果；Markdown/JSON按修订导出，附schema/处理规则版本和资产引用，导出文件修改不自动回写主库。
- [ ] 网页提供原页/原文/清洗结果及改动原因对照，接受、恢复、修正、重试与复核；桌面提供状态与入口。
- [ ] 质量门禁：漏页、关键解析失败不能自动通过；用户可重试、人工修正或显式排除页并记录理由。
**通过条件：** 每项修改能解释与撤销，保护性样例不误改数字/网址/代码；并发编辑不覆盖新修改，人工纠正不被重跑悄悄抹掉。

### 阶段4：来源分片、Chroma索引代际与启用

**文件：** `rag/{structure,chunks,index,service,client}.ts`、网页vectors适配、library激活记录。
- [ ] 从复核版本分片，存入SQLite；保留章节、页码/来源范围、元素编号，表格附表头，问答/代码尽量完整。
- [ ] 清洗文本偏移与原件位置分开保存映射，不把清洗后的字符偏移当成原文坐标。
- [ ] 构建独立候选集合，保持既有模型指纹/维度校验，旧v2集合保留。
- [ ] SQLite索引任务/outbox记录目标修订快照，写向量可重复执行；构建完成核验分片编号、数量和指纹，不仅检查HTTP成功。
- [ ] SQLite事务内复查候选快照与当前资料版本/删除/模式状态，一致才切换活动指针；不一致作废重建。
- [ ] 检索固定一次读取的活动代际，并复核命中片段对应的删除/启用状态。构建中断不影响旧索引。
- [ ] SQLite与Chroma不做假跨库事务：定期核对构建中/待激活任务和缺失集合，提供重试与重建；发现活动集合丢失应明确报错。
- [ ] 回滚正文快照及索引指针；不得隐式恢复当前已删除/禁用资料。旧代际仅提供清理预览，不自动永久删除。
**通过条件：** 并发编辑删除、半写入、崩溃、激活失败、重启恢复、活动集合丢失和回滚均有测试，不能用过期候选替换正式内容。

### 阶段5：复杂布局增强
- [ ] 先评测本地文本块坐标排序，恢复多栏顺序；工具选择同时核对许可、分发、资源成本。
- [ ] 表格检查表头、行列、合并格、跨页关系与关键数字；不可靠时留截图复核，扫描表格另需专门单元格识别能力。
- [ ] 公式/图表先关联原图与上下文；专用公式OCR/本地多模态模型另列资源与效果评测，机器说明不得冒充原文。
**通过条件：** 在人工标注页上验证顺序及单元格，而不是用提取字数作为正确率。

## 三、备份、恢复与维护

- SQLite使用一致性备份接口或受控停写流程，不能在写入期间只复制主文件忽略WAL。
- 备份包含数据库、被引用的原件/资产、模型指纹及索引代际清单；Chroma选择一致性备份或明确从原始记录重建。
- 提供备份manifest/哈希核验和恢复演练；恢复后检查全部引用与活动索引，再开放写入。
- 软删除与资产引用分开处理；清理先计算跨项目/修订引用，不能因一份资料删除就误删共享原件。
- 记录数据库驱动、环境、资产位置与卸载步骤，不删除其他项目的向量集合或共享服务。

## 四、验收、迁移节奏与发布

顺序：0兼容/基线 → 1主库迁移 → 2逐页解析 → 3清洗复核 → 4索引启用 → 小批真实资料评测 → 5复杂布局。

先写专项失败测试再实现，阶段通过后回归测试/类型检查/打包内验证；不同时改所有存储、清洗和检索路径后才验收。

质量验收：页记录100%覆盖；失败和不确定问题可见；来源可追溯；候选未确认时不影响现用版本；无静默截断或数字/网址/代码误改。

效果验收：固定语料、模型、提示词及检索参数，对原20题补充混合页/表格/跨页题，分别报告召回、来源定位、答案正确率、耗时与资源占用，不能把检索命中当成答案正确。

先合成样例，再选定小批课程资料；旧资料可逐批迁移重处理，原件缺失提示补传。不承诺SQLite自身能提高语义准确度，它提供可管理、可追溯和可恢复的基础。

每期交付更新README、数据库升级/备份/回滚说明、操作台账；同步GitHub和pcworkspace前核对用户改动并排除密钥、私人资料、模型与运行库文件。

# Chrys 文档解析与清洗最终实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans task-by-task after implementation is authorized. 本轮只交付计划，不执行功能修改。

**Goal:** 建立全部本地、可追溯、可复核、可撤销的文档处理流程，提高知识库内容完整性与检索质量。
**Architecture:** 文件准入 → 逐页分类 → 分类解析 → 保守清洗 → 统一 Markdown/JSON → 质量检查 → 人工确认 → 候选索引构建与激活。桌面与网页共用核心，主进程及 HTTP 请求只负责提交和查询任务。
**Tech Stack:** 保留 Electron/TypeScript、现有本地 OCR、BGE-M3、Chroma；坐标、图像区域及备用解析能力先做本地样例验证，再锁定依赖。若引入 PyMuPDF 等新工具，先核对许可、打包、模型来源和资源占用，不默认添加云端服务。
**Spec:** 用户提供的五步 PDF 流程、统一结果字段，以及本计划的范围与验收约束。

## 一、当前基础与必须补齐的问题

- `chrys/src/main/knowledge-parse.ts` 已有编码识别、换行与空白整理、空字符删除、部分形似汉字转换。
- `document-pdf.ts` 当前仅依据有无可读字符决定是否整页 OCR，尚未综合图片覆盖、位置、重复页眉与乱码判断。
- OCR/Office 已有独立解析进程和基本资源限制，但主要返回一个文本字符串，没有逐页结构化报告。
- 桌面 `knowledge.ts` 的普通导入保存正文和原文件路径，路径可能失效；网页独立项目能保存原文件。需要统一为受控原文件快照，不能仅依赖外部路径。
- 索引已有文档修订与失效处理；新流程仍需分离“候选清洗结果”和“正式使用版本”，不能生成候选时自动覆盖现用正文或索引。

## 二、范围与约束

- 全部本地处理；安装时允许从已记录的官方来源下载依赖/模型，处理文档时不调用云端解析、OCR或多模态服务。
- 首要对象为 PDF；图片走图像预处理/OCR路线，DOCX、XLSX、PPTX、Markdown、TXT复用统一结果和质量报告。
- 保留原件，不用生成式模型随意纠正文意、数字、网址、代码、公式；不执行宏、脚本、外部图片或文档中的指令。
- 旧资料与当前索引默认保持可用；重新处理按资料显式触发，不批量覆盖。
- 保留现有文件、解压、页数、像素限制作为起点；长任务改为后台任务，不因网页请求断开而丢失任务。页级超时、总时间和重试次数有明确上限，最终阈值经样例测试记录。
- 复杂图表解释、公式转LaTeX不作为前两期完成条件；无法可靠识别时必须留图和复核标记。

## 三、统一结果标准：第一期即落实

文档记录包含 `docId / sourceName / sourceHash / revisionId / parentRevisionId / parserVersion / cleaningVersion / createdAt`。

每页记录包含：
- `pageNumber / pageType / width / height / rotation / methods / status`；
- 元素列表：`elementId / type / text / bbox / order / sourceMethod / assetId`；
- 质量问题：`code / severity / reason / reviewStatus`；
- 清洗改动：`ruleId / elementId / before / after / reason / accepted`。

`bbox` 采用经过页面旋转统一后的左上角原点、0–1归一化坐标，并保留原页面尺寸和旋转信息。规则评分与OCR引擎置信度分开记录；引擎未提供的字段为空，不制造评分。

产出：
1. 不可变原文件快照与必要的页面/图片资产。
2. 带文件、页码和结构的 `parsed.json` 与未经清洗的正文。
3. `cleaned.md`、结构化清洗结果和 `changes.json`。
4. `quality-report.json`，覆盖每一页，包括空白页、失败页和未处理页。

表格可靠时保留结构，否则保留截图与上下文；图片、公式保留页码和位置，说明区分“原文说明”与“自动生成说明”。没有可靠说明时不编造。

非PDF文件不虚构PDF页码：PPT使用幻灯片号，Excel使用工作表/单元格范围，TXT/Markdown使用章节/行范围，DOCX无可靠分页时使用段落位置。

## 四、分期任务与验收

### 第一期：文件体检、逐页路由、统一结果与候选版本

**任务1：统一原件与修订存储**
- 建立文档修订和文件哈希；桌面、网页上传入口都先留存受控原件快照。
- 同一项目内哈希相同且解析/清洗配置一致时复用结果；保留本次导入记录，不跨项目复用权限和启用状态。
- 哈希不变但规则或解析器升级时允许重新处理。
- 只有重新导入同一资料或人工指定关联时创建新版本；不同哈希不自动判定为同一资料。
- 测试重复上传、配置升级、重新导入、原文件被移动、写入失败；验证原件和现用版本不丢失。

**任务2：后台任务与文件体检**
- 任务状态：排队、体检、分类、解析、清洗、待复核、可启用、已启用、失败、已取消；保存进度和错误阶段。
- PDF读取总页数、加密状态和可打开性；密码只在本次任务内存中使用，不进入日志、报告、备份或索引。
- 密码错误/缺失时停止并提示；损坏文件仅在工作副本上尝试一次受限修复，失败保留原因并要求重新提供。
- 保存原件与修复件的哈希和关系，后续从修复件解析；不得覆盖原件。
- 正确应用PDF已有旋转元数据；疑似扫描方向交给图像阶段校正，体检不提取正文。
- 新增提交、查询、取消任务接口和桌面IPC；网页桥接返回jobId，不再用长HTTP请求等待整份文档完成。
- 测试密码、损坏、取消、超时、进程崩溃和重启后任务恢复；只重试未完成页，不把失败页当空白页。

**任务3：逐页分类与分类解析**
- 收集有效文字量/比例、异常字符、图像区域与覆盖率、文字坐标、重复边缘文本、疑似分栏/表格特征。
- 对连续页面先收集特征，再分析重复页眉；短文档证据不足时保守处理。
- 分类为文本页、扫描页、混合页、疑似复杂布局页、异常页；保存分类依据与不确定标记。
- 文本页直接提取元素与位置；扫描页渲染并OCR。
- 混合页定位候选图片区域，仅补识别含文字的区域，结合位置和相似度合并，避免原文/OCR重复。
- 不能可靠区分装饰图与重要图片时提示复核；不声称能自动理解图片语义。
- 乱码页使用备用本地解析路线；仍失败再OCR；无法处理则标记异常。
- 空白页保留页记录但不生成正文，不进入向量索引。
- 测试带页码/水印的扫描页、有截图的文本页、纯文本页、乱码、空白和分类不确定页面。

**任务4：统一输出与基础质量门禁**
- 以原页码为主键汇总所有页面，逐页注明成功、空白、失败、取消或未处理，页记录不得缺号。
- 检查乱码、空提取、重复文本、疑似阅读顺序及低质量OCR；每条警告能定位原页。
- 文件无法打开、漏页记录或关键页失败时阻止整份资料直接标为通过。
- 用户可重试、修正正文、标记已复核或显式排除问题页；排除须记录原因，不静默跳过。
- 验收：Markdown与JSON页序一致；结果中的元素、警告均可追溯原件；任务失败不改现用正文或索引。

### 第二期：保守清洗、预览复核、索引激活

**任务5：按页面位置清洗噪声与断行**
- 页眉/页脚检测结合边缘位置、跨页频率、内容相似度；页码结合位置与数字序列。
- 水印单独考虑跨页重复、覆盖位置和可获得的样式；不局限于顶部底部。
- 所有移除先生成候选改动；保留原元素，允许恢复，正文重复句不能仅凭频率删除。
- 段落断行修复结合行坐标、标点、缩进、字体特征；保护标题、列表、代码、表格和公式。
- 英文断词仅在证据充分时合并；数字、链接、命令和专有名词不猜测替换。
- OCR进行可选旋转、去倾斜、对比度增强；保留变换与坐标映射，质量变差时回退原图识别。
- 测试正文重复句、短文档、奇偶页不同页眉、跨页段落、代码缩进、中文列表、URL和表格数字不受误改。

**任务6：网页清洗预览与复核**
- 新增处理报告、按页筛选、原页/原文/清洗结果对照、修改原因、接受/恢复操作。
- 支持修正文字、逐页重试、标记已复核；保留人工改动，重新清洗不得无提示覆盖。
- 明确区分“解析完成”“质量待复核”“索引已启用”，避免误以为上传完成即投入回答。
- 整页图片按需加载；页面资产通过现有本机会话授权返回，不暴露任意本机路径。
- 桌面提供任务状态及打开处理报告入口，避免复制两套复杂编辑器。
- 测试保存期间继续输入、过期版本冲突、取消后残余任务、前后端断线恢复和资产访问边界。

**任务7：可追溯分片与安全启用**
- 确认后的正文进行结构化分片；片段携带文档版本、原始文件名、页/位置范围、章节和元素引用。
- 表格片段附相关表头；问答、代码和受保护结构尽量保持完整；跨页片段保留全部来源范围。
- 清洗后的偏移只指向清洗正文，另存来源映射，不将偏移直接冒充原文位置。
- 引入v3可配置索引代际：桌面集合为 `shiping_knowledge_bgem3_v3_<generation>`；网页集合保留 `rag_admin_` 前缀并附代际。BGE-M3不变，原v2集合保留。
- 按知识库生成完整候选代际；构建并校验文档修订、数量和向量维度后，原子切换活动指针。切换前修改或删除资料则使候选过期，必须重建，不能激活旧内容。
- 检索请求固定使用一次读取的活动代际；取消、崩溃、部分写入时仍使用旧代际。
- 回滚同时恢复正文活动修订和索引指针；若回滚会恢复已删除/禁用资料，必须显式提示，不绕过当前启用状态。
- 保留旧代际，不自动永久删除；提供容量与清理预览。
- 测试构建中编辑/删除、并发激活、指针写入失败、重启、回滚及旧v2兼容。

### 第三期：复杂布局增强（独立里程碑）

**任务8：坐标排序与表格恢复**
- 对多栏样例评测本地坐标排序与布局解析候选，选择可复现且许可合适的方案。
- 文本表格提取后检查表头、行列、合并格、跨页关系和关键数字；不可靠时留截图并复核。
- 扫描表格需要独立单元格识别能力；普通OCR文字不视为表格恢复成功。
- 使用人工标注页验收阅读顺序和单元格对应关系，不以文本量增加代替准确率。

**任务9：公式与图表**
- 先交付图片、页码、位置与上下文关联。
- 专用公式OCR或本地多模态模型先做资源/效果评测；模型下载、磁盘、内存和耗时单独列出。
- 公式转换及图表说明始终注明机器识别来源；低可靠结果不直接当成已核实事实。

## 五、代码落点

新增共享类型 `chrys/src/shared/document-processing.ts`。
新增核心目录 `chrys/src/main/document-processing/`：preflight、page-classifier、page-parser、cleaner、result、quality、jobs、revision-store，各司一职。
扩展现有 `document-worker.ts`、`document-pdf.ts`、`document-import.ts`，逐步兼容原有字符串解析入口。
更新桌面 `knowledge.ts`、`knowledge-admin.ts`、共享资料类型及IPC；网页 `store.ts`、`server.ts`、`bridge.ts`、public界面共用任务与修订流程。
更新 `rag/structure.ts`、`chunks.ts`、`index.ts`、`service.ts`、`client.ts` 和网页向量适配器，传递来源映射并支持索引代际。
新增合成解析/清洗/任务/并发/索引切换测试，避免测试读取真实文档与密钥。

## 六、旧资料迁移和备份

1. 备份当前原文、元数据、Chroma及活动索引记录。
2. 原有资料标为旧格式，继续按现有方式回答，不伪造页码或哈希。
3. 有原件快照或原路径仍可访问时，按选择生成候选；找不到原件则保留现有正文，并提示重新上传以获得页面级追溯。
4. 先处理合成样例，再处理用户选定的小批资料；复核后切换v3。
5. 备份覆盖原件、修订、页面资产、报告及活动指针；明确JSON资料导出与完整备份的区别。
6. 记录新增环境/模型/资源位置与卸载方式；不自动移除共享向量服务或其他项目集合。

## 七、统一验收与发布

- 先写失败测试，再实现；每个任务通过专项测试后提交，阶段结束跑全套回归、类型检查和打包内实际解析。
- 合成标注样例覆盖五类页面、旋转、密码、损坏、超限、乱码、重复页眉、水印、多栏、表格、混合图片和取消恢复。
- 页记录覆盖率必须100%；故障/漏处理必须报告，不得假报成功。
- 保护性样例中数字、URL、代码不得因清洗被误删或改写；候选噪声误判必须可恢复。
- 课程资料人工标注集另行建立，比较漏提取、噪声残留、阅读顺序和表格关键值；分类与质量阈值在该样例集上校准，不宣称固定规则适用所有文档。
- 复用原20道问题并补充混合页/表格/跨页问题；固定同一语料、模型、提示词和检索参数，分别报告召回、来源定位、答案正确率、耗时和资源变化。检索命中不等于回答正确。
- 旧正式索引在候选构建、失败、取消及未确认期间保持可用。
- 每期通过后更新README、安装/备份/回滚说明、操作台账；同步GitHub与pcworkspace前检查新增改动，排除密钥、私人资料、模型及运行数据。

## 执行顺序与交付边界

第一期任务1–4 → 第二期任务5–7 → 小批课程资料对比验收 → 第三期任务8–9。
统一结果标准属于第一期必交付，不留到最后补做。前两期完成意味着“能检测问题、保留证据、复核后安全投入检索”，不意味着所有版式、图表和公式均已被正确理解。
